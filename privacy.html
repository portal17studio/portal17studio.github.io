Privacy Policy

Last updated: October 29, 2026

Your workflows run on your computer. Portal17 Studio does not automatically upload your projects, secrets or diagnostic reports to us, and does not send us usage analytics. Actions and triggers you configure can exchange data with websites, databases, email providers, Microsoft Teams, an AI provider you choose, APIs and optional Cloudflare tunnels. This policy explains those connections and the information saved locally.

This policy covers the Portal17 Studio desktop application and portal17studio.com, including its demos and practice sandbox. It applies to all interface languages. “We” refers to Portal17, the developer and publisher of Portal17 Studio. See our publisher and contact details. Services you connect to, the Microsoft Store and this website's hosting provider also have their own privacy policies.

Data stored on your computer

Portal17 Studio processes your automation locally. It does not require a Portal17 account or provide a publisher-operated cloud service for storing your projects.

  • Projects and data: .portal files contain the nodes, connections, properties, constants and tables you save. Variables are used during execution; exports, downloaded files and other outputs are written to the locations you configure. These files can contain personal or business information handled by your flows.
  • Preferences and history: the app saves settings, workspace and open-file paths, trigger configuration and execution history in .portal17studio within your Windows user folder. Logs and history can include flow names, paths, timestamps, status and error details.
  • Browser sessions: automation uses a browser on your computer. If you enable the persistent browser profile, cookies, sign-in sessions and website storage can remain in the local browser-profile folder between runs.

Ordinary project files, settings, exports and logs are not all encrypted by the app. A folder synchronized by OneDrive, another backup service or a shared drive is subject to the access and synchronization settings of that service.

Browser and Windows recording

When you start recording, the enabled browser and/or Windows recorder captures interactions to create editable nodes. Depending on the action, this can include clicks, keystrokes, entered text, selected values, page addresses, application and window names, and control selectors.

Desktop recording can read clipboard content used in recorded copy-and-paste actions and save control image snapshots for selector repair. Screen capture, image extraction and OCR actions also process the content you target. Text and images saved in a flow or output file may contain information visible in the source application.

Recognized password fields are stored through the local Secrets feature and referenced by name in recorded nodes. Other sensitive text, unrecognized password fields and visible information in images are not guaranteed to be concealed. Review recorded flows and images before sharing them.

Passwords, tokens and Secrets

The Secrets feature encrypts values locally using AES-256-GCM. On Windows, the encryption key is protected with Windows Data Protection API (DPAPI), tied to the Windows user profile. This store includes saved passwords and OAuth access and refresh tokens. Copying its encrypted files alone to another Windows user does not normally allow them to be decrypted.

Versions that used an unprotected local key migrate that key when the updated app accesses the store: the app saves and verifies the DPAPI-protected key before removing the old key file. Existing backups can still contain copies created by an earlier version. Non-Windows development environments do not provide Windows DPAPI protection.

A flow can reference a secret by name instead of embedding it in a .portal file. OAuth-connected mail nodes store a connection identifier rather than the account's tokens. The app also uses its local secret store for IMAP passwords, webhook signing secrets and Cloudflare tunnel tokens.

Encryption does not protect against every threat, including malicious software running as the same Windows user or a compromised device. Ordinary node properties, constants, message data, exports, reports and files are not all encrypted by the app. Authentication sends the credentials or tokens needed for a connection directly to the corresponding service over the connection it requires.

Connections you configure

Local execution does not mean that every workflow is offline. Your nodes can send and receive information through the connections you choose:

  • Websites and APIs: navigation, form entry, file uploads and API calls exchange the addresses, request data, files and authentication information needed for those actions with the destination service.
  • Databases: SQL actions connect to the database you specify and exchange authentication information, queries and results. That database may be on your computer, on your network or hosted remotely.
  • Email: Read Emails, email triggers and Send Email can use your OAuth-connected mailbox or the other account methods you configure. Send Email can use classic Outlook installed on your computer, an OAuth-connected mailbox or your manual SMTP provider. Local Outlook access uses its configured profile and account session. Sender and recipient addresses, message contents and attachments are sent to that provider and the intended recipients.
  • Microsoft Teams: Send Teams, Read Teams, Wait for Teams Reply and the Teams message trigger use your connected Microsoft work or school account through Microsoft Graph. Message text, recipients, team and channel names you configure are sent to Microsoft and delivered to the people or channel you choose. See Microsoft Teams below.
  • AI: the Process with AI node and the AI Assistant use the AI option you set up. The built-in engine and your own local-network server keep the data on your computer or network; a cloud AI provider receives the texts and questions sent to it. See AI features below.
  • Files and other programs: flows can read, write or launch resources you select, including shared folders and programs with their own network connections.

These exchanges are part of your automation, not uploads to the Portal17 Studio publisher. The destination's privacy policy, access rules and the connection settings you choose apply to that information.

Gmail, Microsoft and connected email accounts

Connecting an email account is optional. Before connecting, you can review this policy from the app's connected-mail controls. Google or Microsoft presents its own sign-in and consent screen in your browser. Portal17 receives authorization tokens after you approve access; it does not receive your Google or Microsoft account password through this OAuth sign-in.

What email data the app accesses

For the mailbox and folders you select, connected-mail actions can access your email address, message identifiers, folder information, senders and recipients, subjects, timestamps, message bodies and attachments. Read Emails makes selected message data available to your flow. Email triggers check for new messages, maintain local checkpoints and can save attachments locally for the flow. Send Email processes the recipients, subject, text or HTML body and attachments specified by your flow.

Gmail IMAP/SMTP OAuth uses the restricted scope https://mail.google.com/. Google describes this permission as allowing reading, composing, sending and permanently deleting email. Portal17 uses it for the email features described here because Gmail's IMAP/SMTP authentication requires that scope. The current connected-mail actions do not offer a permanent-delete operation. Marking messages as read or moving them between folders happens only when configured in the flow. Microsoft connections request the corresponding IMAP and SMTP permissions and offline access for token renewal.

How email data is used

Email data is used to perform the automation you configure: read and filter messages, extract information, save attachments, run a flow when a message arrives, optionally mark or move processed messages, and send messages to your chosen recipients. Schedules and enabled background triggers may perform these operations while the editor is closed. Connecting an account alone does not send an email; sending requires a configured Send Email action to execute.

We do not use Google user data for advertising, sell it, provide it to data brokers, or use it to train generalized artificial-intelligence or machine-learning models. We do not routinely inspect users' mailbox data. If you choose to send us a support message or report, we receive the material you explicitly share and use it for that request.

Where data is stored and who receives it

Portal17 connects directly from your computer to Google or Microsoft using encrypted transport. The publisher does not operate a mailbox synchronization server or receive a copy of your OAuth tokens or messages as part of connecting, reading or sending mail. Tokens are saved in the local encrypted Secrets store described above. Connection metadata, such as the provider, email address and connection label, is stored locally and is not all encrypted.

Message data can remain in local workflow results, saved projects, tables, exports, attachment folders, logs or reports, depending on the actions you run. Such files may contain personal information and are not automatically all encrypted or redacted. This includes screenshots or error reports that capture visible email data.

Google or Microsoft processes the authentication and mailbox requests. For sending, your email provider and the recipients receive the message and attachments. Your own workflow may also deliberately transfer selected email data to destinations you configure, such as an API, another email address, a database, a website or a shared or synchronized folder. Those transfers serve the automation you request, are under your control and are subject to the destination's policies. Portal17 does not independently disclose mailbox data to advertising, analytics or data-broker services.

Portal17 Studio follows the Google API Services User Data Policy and its Limited Use requirements when handling Google user data. Use and transfers of that data are limited to providing or improving the user-facing features described here, in accordance with that policy.

Retention, disconnection and deletion

Saved authorization tokens remain on your computer until you disconnect or remove the connection, replace them through a new sign-in, or delete the relevant local data. Tokens may expire or be revoked by the provider. A connection's saved token can be renewed in the background while the connection is authorized and used by enabled features.

In the connected-mail manager, Disconnect removes the saved access and refresh tokens for that connection. Remove connection also removes its connection metadata and saved application credential entry. To revoke the provider-side authorization, remove Portal17 Studio from your Google Account connections or the corresponding Microsoft account or organization application settings.

Disconnecting does not erase emails already stored by your provider, delivered messages, downloaded attachments, exported data, saved flow content or backups. Delete those copies in their respective locations. Stop related flows and disable schedules and triggers when you no longer want them to access email. If you sent email data directly to our support address, you may request its deletion using the contact details below, subject to applicable obligations.

Microsoft Teams

Connecting Teams is optional and separate from connected email. Microsoft presents its own sign-in and consent screen in your browser; Portal17 receives authorization tokens after you approve access and does not receive your password. Depending on your organization's settings, an administrator may need to approve the permissions before you can connect.

Permissions and the data the app accesses

The Teams connection requests these delegated Microsoft Graph permissions: User.Read (your own profile and email address), User.ReadBasic.All (basic profile of the people you message, to find them by email), Chat.Create and Chat.ReadWrite (open and read your one-to-one chat with a person), ChatMessage.Send (send chat messages), Team.ReadBasic.All and Channel.ReadBasic.All (find a team and channel by name) and ChannelMessage.Send (post to a channel) and Files.ReadWrite.All (upload the files you choose to send and download the files sent to you, using your own access), plus offline_access for token renewal. Delegated permissions mean the app acts only as you and can only reach what your own account can reach.

Send Teams sends the text or HTML message your flow specifies, on your behalf, to the people or channel you choose. Read Teams reads the messages of your one-to-one chat with the person you specify (sender, date, text and message identifier) into a local data table for your flow. Wait for Teams Reply sends a question in that chat and checks it periodically until the person answers or the time limit is reached. When a node attaches files, they are uploaded to your OneDrive (for chats, and shared read-only with the recipients) or to the channel's files folder (for channels), as Teams itself does. When you choose a folder to save attachments in, the files and pasted images of the messages read are downloaded to that folder on your computer. If you enable a When a Teams message arrives trigger, the app periodically checks your chats for new messages (sender name and email, text, time, chat type and topic) on your computer, applies your filters and starts your flow with the matching message, saving its files in a local folder if you enable it; it keeps only a local note of the last message checked. The app does not read channel messages, and does not read your conversations unless a node or trigger you configure does so.

How Teams data is used, stored and shared

Teams data is used only to perform the automation you configure. The app connects directly from your computer to Microsoft Graph using encrypted transport; the publisher does not operate a server for Teams and does not receive your tokens or messages. Tokens are saved in the local encrypted Secrets store described above; connection metadata such as the account address and label is stored locally. Messages read by a flow can remain in variables, tables, exports, logs or reports you create, and your own flow may deliberately send them to other destinations you configure. We do not use Teams data for advertising, sell it or use it to train artificial-intelligence models.

Disconnecting the Teams account in the app removes its saved tokens; removing the connection also removes its metadata. To revoke the authorization on Microsoft's side, remove Portal17 Studio from your Microsoft account or organization's application settings. Messages already sent remain in Teams and are governed by your organization's and Microsoft's retention rules.

AI features

AI is optional. The Process with AI node sends the text and instruction you configure to the AI to answer, extract fields or classify it. The AI Assistant panel sends your question together with the open flow, the selected node and its fields, and the last lines of the console, so it can explain how to do something or why a run failed. Passwords and Secrets are never included in what the Assistant sends.

Where the AI runs

  • Built-in engine (default): runs entirely on your computer. Nothing you process with it is sent to us or to the internet. Setting it up downloads, once, the open-source engine from GitHub and the model you choose from Hugging Face; those services see an ordinary download request, such as your IP address. The files are stored on your computer and you can delete the models from the AI settings.
  • Your own server: an Ollama, LM Studio or OpenAI-compatible server on your computer or local network. The app refuses internet addresses for this option, so the data stays inside your network and is handled by that server.
  • Cloud provider (optional): if you choose Claude, ChatGPT, Gemini, Mistral, OpenRouter or another OpenAI-compatible service and enter your own API key, the texts processed with AI and your questions to the Assistant, with the context described above, are sent from your computer directly to that provider and billed to your account with them. Their terms and privacy policy apply, including how long they keep the data and whether they use it. Portal17 does not receive this data or your key.

API keys are saved encrypted in the local Secrets store, protected with your Windows account. The Assistant's conversation is not saved to a file; results of Process with AI stay in the variables, tables, logs or files your flow creates. We do not use what you process with AI to train models.

Triggers, webhooks and background execution

Enabled triggers can monitor the folders, files, applications, email accounts or Teams chats you configure. Outlook, IMAP and OAuth-connected email triggers can make sender and recipient details, subjects, message bodies and attachment information available to your flow. Trigger settings, checkpoints and execution logs are kept locally.

The webhook listener accepts requests on your own computer. It listens on the local loopback address by default; allowing access from your network is optional. Incoming request bodies, headers and query values can be passed to the flow and handled by its actions.

If you enable a public Cloudflare tunnel, webhook requests travel through Cloudflare to your local listener. This can involve request content, IP addresses and traffic metadata. Both temporary tunnels and tunnels configured through your own Cloudflare account use that provider's infrastructure. See the Cloudflare Privacy Policy.

Optional background execution can keep enabled triggers running after the editor closes. Scheduled flows run through Windows Task Scheduler. Their data handling is the same as when you run the flow manually; closing the editor alone does not disable a background service or a scheduled task.

Diagnostics, screenshots and error reports

The app does not automatically send diagnostic or failure reports to us. Diagnostic tests and execution logs are generated on your computer. A saved diagnostic report can include the app and Windows versions, display and keyboard information, test results and error details. The web connectivity diagnostic makes a request to this website's sandbox.

When an action exhausts its failure handling, the app can create a local report in .portal17studio/reports. It can contain a screenshot of the full desktop across your monitors, a screenshot of the current automated browser page, the page address and title, node properties, error information and details of visible Windows controls.

Some recognized credential property names are masked in the text report. Screenshots and arbitrary text are not guaranteed to be redacted and may include personal or confidential information. Review and redact reports before sending them to anyone. Reports reach us only if you choose to share them, for example with a support request.

Retention and your control

Your saved projects and outputs remain in their chosen locations until you remove them. The local execution history retains up to 300 entries and can be cleared in the app. The app attempts to retain the 20 most recent failure-report folders; separately saved diagnostic reports and other logs may remain until you delete them.

You can stop recording, disable triggers and public tunnels, turn off background execution, remove scheduled Windows tasks, clear execution history, remove saved Secrets, and delete projects, exports, browser-profile data and reports. Close the app and stop its background service before removing its configuration files. Removing a secret's key also prevents the app from decrypting the remaining secrets.

Uninstalling the app should not be relied on to delete every project, output or user configuration file. Deleting local files does not remove copies in backups or data already delivered to a website, database, email recipient or other service; those copies follow the destination's rules.

Microsoft Store and Windows

Microsoft handles Store installation, purchases, updates and related account information. Windows and the Store may also process diagnostic information according to your Microsoft settings. This is separate from the app's local workflow data. See the Microsoft Privacy Statement.

This website, demos and sandbox

portal17studio.com is a static website hosted on GitHub Pages. It has no Portal17 user accounts, advertising trackers or analytics scripts, and its own pages do not set cookies. GitHub logs visitors' IP addresses for security purposes when serving GitHub Pages sites, including visits without a GitHub account. See GitHub Pages data collection and the GitHub Privacy Statement.

The interactive demos, playground and practice sandbox run in your browser. Their practice forms do not submit entered values or selected files to a server; their state resets when you reload. Use sample information for practice. Loading pages, images and the demo video still makes normal requests to the hosting provider.

Links to the Microsoft Store, connected services or other external websites take you to services governed by their own policies.

Contact and information you share

If you email us, we receive your email address, message and any attachments you choose to send. We use that information to respond to your request and handle the related support or privacy issue. Do not include passwords, API keys or unredacted confidential reports.

For questions about this policy or information you have shared directly with us, contact contact@portal17studio.com. You can use the same address to request access to, correction of or deletion of information you have sent us, subject to applicable obligations. We cannot delete data held independently by services you connect to.

Children's privacy

Portal17 Studio is not directed at children under 13. We do not knowingly solicit personal information from children. If you believe a child has sent us personal information, contact us so we can address it.

Changes to this policy

We will update this page when the app's data handling or the website's services change and revise the date above. The current policy describes local storage and the optional connected features in Portal17 Studio, including connected email, Microsoft Teams and AI. When a change affects how Google user data is accessed, used, stored or shared, we will also notify affected users in the app, before the changed use, and obtain any additional consent required. Features described here may require an updated desktop version.
